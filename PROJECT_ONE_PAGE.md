Krishi Setu is a full-stack gamified learning platform designed for sustainable farming education, built to improve engagement, retention, and practical adoption of agricultural best practices among farmers, students, and rural learners through interactive digital experiences instead of passive text-only learning. The project name is Krishi Setu: A Gamified Learning Platform for Sustainable Farming Practices, and it sits at the intersection of AgriTech, EdTech, and behavioral gamification. The core problem addressed by this system is that traditional agriculture training is often difficult to sustain over time due to low interactivity, low motivation, and limited progress visibility, which results in poor continuity of learning and inconsistent application in real-world farming. The platform aims to make agricultural education engaging, measurable, and repeatable by combining authentication, personalized user journeys, learning content, dashboards, and game-driven tasks. The main objective is to build an accessible digital platform where users can register, log in securely, participate in gamified farming activities, track performance, and continuously improve through feedback loops powered by score and accuracy data. The intended users include practicing farmers, beginner learners, agricultural trainees, and administrators who manage or monitor user engagement flows. The project currently uses a frontend based on static HTML, CSS, and JavaScript pages and a backend API based on Node.js and Express, with supporting packages such as bcryptjs for password hashing, jsonwebtoken for token-based sessions, dotenv for configuration management, cors for cross-origin requests, concurrently for full-stack development startup, and http-server for frontend hosting. The architecture follows a practical layered model where the user interface and client logic are placed in Frontend pages and scripts, the service layer is implemented in the backend server runtime, and persistence is handled through local file storage in users.json, making it ideal for prototyping, demonstrations, and small-scale deployments. Security and data handling are designed with baseline best practices for student and prototype systems: passwords are hashed using bcrypt, authenticated routes rely on JWT bearer tokens, sensitive runtime configuration values are kept in environment variables, and route access is guarded from both client and server sides. The implemented features include user registration with validation, user login using identifier and password, admin login through configured credentials, protected profile fetch endpoints, health and availability checks, gameplay statistics submission endpoints, and frontend route guards that ensure session-based access to protected pages such as dashboard and learning views. The platform also supports measurable user progress with game-related metrics such as games played, total score, accuracy trends, win streak progression, and per-game best scores, which can be used as evidence variables for thesis analysis and impact evaluation. From an academic perspective, this project can be presented as a design-and-development study where requirements are analyzed first, user-facing experiences are implemented iteratively, backend interfaces are validated through smoke tests, and integrated behavior is confirmed through endpoint-level runtime verification. A suitable thesis methodology narrative can describe requirement analysis, system design, implementation, integration, test-based validation, and iterative debugging based on observable runtime outputs. Suggested evaluation indicators include authentication success rate, API endpoint reliability, response consistency, user engagement progression over time, completion rates of daily tasks, score improvement across repeated play sessions, and usability feedback from test participants. The system currently has known constraints that should be documented honestly for research quality: file-based storage is not intended for high concurrency or large-scale production, analytics depth is currently moderate, and automated CI-level regression testing is not yet fully integrated. Despite these limitations, the project is highly extensible and can be advanced in future work by migrating to a production database such as MongoDB or PostgreSQL, adding personalized recommendation modules for crop-specific learning pathways, creating richer analytics dashboards for cohort-based evaluation, adding offline-first mobile support for low-connectivity environments, strengthening security hardening and rate-limiting policies, and integrating multilingual accessibility plus voice-based guidance. In practical operation, the backend runs on port 3001 through npm scripts, frontend and backend can be started together for full-stack execution, and health checks can be used to verify service availability before user flow testing; if health checks fail with connection refusal, the immediate action is to start the backend process and retest. This project is therefore suitable both as a functional educational platform prototype and as a thesis-aligned applied software engineering case study demonstrating problem-driven design, measurable gamification outcomes, and scalable future research potential in digital agriculture.
